# 🥖 Mr. Baton — Бюджетный хаотичный бот

> **Очень характерный и очень дешёвый** Telegram-бот.  
> Работает **только** на GLM + Gemini через OpenAI-совместимые API.  
> Никакого Claude. Простой, быстрый и с очень сильным характером.

**Главная фишка** — он реально сделан для живых семейных и дружеских групп. Не корпоративный помощник. А именно поехавший член чата, который иногда несёт хуйню, но при этом реально помогает и стоит копейки.

## Почему этот бот не такой, как все остальные

Обычные Telegram-боты обычно:
- Начинают объяснять шутки
- Зацикливаются на старых темах
- Говорят "у меня нет доступа к визуальному восприятию"
- Пишут с большой буквы

**Mr. Baton** заточен именно против всего этого.

Он:
- **Жёстко** пишет только с маленькой буквы (это не баг, это фича)
- Имеет мощную анти-систему против зацикливания на старых мемах
- В группах работает в режиме "цифрового ребёнка" (Окситоцинка) с отдельным характером
- Умеет молчать, когда нечего сказать (`[молчу]`)
- Видит картинки через отдельный Gemini vision-эндпоинт
- Работает на дешёвых GLM-моделях и при этом остаётся очень живым

## 🧠 Философия проекта (самое важное)

- **Характер важнее интеллекта.** Лучше хаотичный, но очень живой бот на дешёвых моделях, чем умный, но пресный.
- **Контекст — это яд.** Чем больше истории ты суёшь модели — тем сильнее она зацикливается на старых шутках. Поэтому очень агрессивная обрезка памяти.
- **Группа — это не личка.** Отдельный лёгкий путь + отдельный промпт под семейный троллинг и абсурд.
- **Никогда не признавайся в слабости.** "У меня нет доступа к картинкам", "я не могу искать в интернете" — это табу.
- **Только бюджетный стек.** GLM + Gemini через OpenAI-совместимые API. Никакого Claude.

## 🚀 Установка и запуск

### 1. Зависимости

```bash
pip install -r requirements.txt
```

### 2. Конфигурация

```bash
cp .env.example .env
```

Открой `.env` и заполните минимальные параметры для запуска:

```ini
TELEGRAM_BOT_TOKEN=123456:ABC...         # от @BotFather

# --- Основной путь (GLM) ---
OPENAI_API_KEY=твой_ключ
OPENAI_BASE_URL=https://api.z.ai/api/paas/v4
OPENAI_MODEL=glm-4.5-flash

# --- Vision (рекомендуется) ---
OPENAI_VISION_API_KEY=
OPENAI_VISION_BASE_URL=
OPENAI_VISION_MODEL=gemini-2.5-flash

# Модели (только GLM + Gemini)
MODEL_FAST=glm-4.5-flash
MODEL_SMART=glm-4.5-flash

# Параметры генерации
MAX_TOKENS=1024
MAX_TOKENS_DOC=2048
TEMPERATURE=0.6

# Память и лимит контекста
HISTORY_ROUNDS=10
MAX_HISTORY_MESSAGES_PER_CHAT=8
MAX_CONTEXT_CHARS=8000

# Учитывать 8K‑лимит для GLM‑4.5‑Flash? Если false — бот не будет
# обрезать историю и контекст, что может привести к throttling на
# бесплатном тарифе Z.ai. true по умолчанию.
RESPECT_GLM_8K_LIMIT=true

# Сеть
REQUEST_TIMEOUT=60
```

### 3. Тест подключения (до запуска Telegram)

```python
from bot import openai_client
print("Подключение готово")
```

### 4. Запуск

```bash
python bot/main.py
```

## 🗂️ Workspace и файлы

- Присланные файлы сохраняются в `data/<chat_tag>/files/` — у каждого чата
  своя папка.
- Метаданные хранятся в `data/<chat_tag>/workspace.json` вместо глобального
  `data/workspace.json`.  Это упрощает структуру и исключает пересечение
  данных между чатами.
- Файлы удаляются автоматически через `WORKSPACE_TTL_HOURS` часов
- Ручная очистка: `/clear`
- Поддерживаемые форматы для **чтения**: txt, md, csv, json, pdf, docx, xlsx, png, jpg, jpeg, webp, gif
- Поддерживаемые форматы для **создания**: txt, md, csv, json, docx, xlsx, pptx

## 🔥 Как это выглядит в жизни (vibe check)

Типичные реакции в семейной группе:

- кидают фотку → "пиздец какая фотка ахах"
- кто-то несёт хуйню → "ладно, это уже перебор"
- старый мем про картошку пытается всплыть через 7 сообщений → бот делает вид, что не помнит
- "напомни через 40 минут купить хлеба" → реально ставит напоминание, а не говорит "ок, напомню"

Это не "бот, который помогает". Это **бот, который участвует в жизни чата**.

## 📚 Agent Tools Layer

**Как это работает:**
1. Модель видит `TOOLS_SCHEMA` — список всех доступных инструментов
2. Модель анализирует запрос пользователя и решает, какой инструмент нужен
3. Модель возвращает `tool_use` block с именем инструмента и аргументами
4. `dispatch()` выполняет инструмент и возвращает результат
5. Результат возвращается модели, которая формирует финальный ответ
6. Пользователь получает только текстовый ответ (без JSON/debug)

**Как добавить новый инструмент:**
1. Добавить определение в `bot/tools.py` в `TOOLS_SCHEMA`
2. Добавить handler в `_dispatch()`
3. Обновить `bot/prompts.py` если инструмент публичный
4. Проверить: результат JSON-serializable, нет падающих exceptions
